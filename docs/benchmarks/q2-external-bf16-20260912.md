# BF16 cached inference: one measured request per backend

The revised PR17 benchmark completed one excluded feasibility/warmup request
and one measured request per backend. Both generated the same **64 token IDs**
from the fixed 128-token W1 prompt, using four loops and greedy decoding.
All four requests, measured CPU controls, cache checks and final cleanup passed.

| Backend | Delivery latency | Output tokens/s | TTFT | Mean decode interval |
| --- | ---: | ---: | ---: | ---: |
| Native vllm-lt | 3.802676 s | 16.830252 | 68.370 ms | 59.275 ms |
| Pinned HF cached adapter | 4.336439 s | 14.758655 | 66.901 ms | 67.770 ms |

Native had 14.04% higher observed output throughput in this single pair.
Repeatability was not measured. This is a batch-1 latency spot check; it does
not establish task accuracy, adaptive behavior or concurrent serving throughput.
Final synchronized latencies were 3.802749 s and 4.336507 s respectively.

## Fixed setup

- Execution source: `d4ee6fd0e1ffdefb0d1907207fcfb9c04eafacb2`, clean checkout.
  The native production files match PR14 `5aa3bf7`.
- Model: `ByteDance/Ouro-1.4B`, revision
  `574fa66cb8bf5abdc979642d01cf2b79b16bfab1`. All shared parameter records and
  official KV tensors were verified as `torch.bfloat16`. Existing selective
  FP32 arithmetic is documented in the [benchmark guide](https://github.com/hsliuustc0106/vllm-lt/blob/526a065721075a2f7809e26ba6b45ac3ca3c59cc/docs/benchmarks/q2-external-bf16.md).
- GPU: NVIDIA L20X, physical GPU 2,
  UUID `GPU-cbf66259-f4ab-0ede-1811-82037dde5924`. CPU 12, memory node 0,
  one intra-op/inter-op thread; SMT sibling 124 monitored. Both backends used
  the same scheduler reservation. TF32 and reduced-precision matmul reductions
  were disabled.
- Reused environment: PyTorch 2.13.0, Transformers 4.55.0, Triton 3.7.1,
  huggingface-hub 0.36.2 and tokenizers 0.21.4. No checkpoint download or
  environment installation was included in execution.
- One model load: 1.482653 s; complete model/adapter preparation: 5.417064 s.
  The worker, including preparation, four requests and cleanup, took 29.489025 s.
  Warmups, detailed cache inspection, CPU counter reads and artifact writing
  are excluded from measured token delivery.
- Native pool: 3,221,225,472 bytes, resident for both backends. The official
  cache retained 96 distinct depth/layer slots, each with 191 positions.
  Final allocated/reserved memory was 0/0; GPU 2 was available with 0 MB after
  the task, and the worker/controller processes had exited.

Measured background CPU activity was 0.021032 cores for native and 0.020749 for
HF, below the 0.1-core limit. Main-thread runnable delay fractions were
0.011761 and 0.012491, below the 0.05 limit. This screen does not guarantee
exclusive host resources or replace repeated measurements.

GPU 0 became occupied after initial preparation. Its task-owned queue entry
was cancelled before any worker, model load or inference started. A new plan
bound both backends to available GPU 2; both plans and the change are preserved.
Exactly four GPU requests ran, with no retries or replacement observations.

The earlier GSM8K-87 timings used source `4ff6f10`, natural stopping, the HF
`generate()` API and a different reduction setting. They are separate evidence
and are not pooled with this fixed-length cached-adapter measurement.

- The original FP32 report also replays byte-for-byte. Its separate final

  results do not rewrite or qualify that historical experiment.

The one-off Q2 harness has been removed from the active source tree. Historical
report replay requires the [recorded harness revision](https://github.com/hsliuustc0106/vllm-lt/tree/d4ee6fd0e1ffdefb0d1907207fcfb9c04eafacb2),
which contains the original report command.

The report's `passed` field covers completion and the declared v2 controls.
`equivalence.passed=true` records token agreement for this prompt only.
`variation.status=single_observation` explicitly records the absence of a
repeatability estimate. The broader Q2 accuracy milestone remains separate.
