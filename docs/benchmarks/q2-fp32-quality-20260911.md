# Q2 FP32 quality baseline — 2026-09-11

The frozen 64-example GSM8K screen completed and scored **4/64 correct (6.25%)**. This is poor observed task quality under the declared prompt/parser and 256-token cap. It establishes a reproducible FP32 baseline; it does not establish acceptable quality, paired non-inferiority, BF16/adaptive qualification, or full [Q2 #8](https://github.com/hsliuustc0106/vllm-lt/issues/8) completion. PR18 remains draft with those limitations visible.

## Verification and acceptance

The frozen standalone CPU scorer ran once and returned `evidence_status=complete`, `decision=complete`, with no missing, corrupt or failed records. Its exact result SHA256 is `cd430dd4a710c2a188e04a37693c60210d9c7d1160e182404ae188c4f25a33ba`. The report label `complete` concerns execution/evidence, not a quality pass. Meaningful CPU tests for selection/parser/plan/scorer/controller and EOS/deadline/lifetime edges passed128/128 in23.27s; Ruff and formatting passed. Production code was unchanged, so no new full legacy suite was run for this harness-only change.

The independent auditor ran once without importing the project parser/scorer or Torch. It rebuilt the 1,319-example selection, re-decoded all 66 actual histories and independently checked Decimal answers, ACK chains, controls and cleanup. It reproduced every outcome with no errors in105.141s, reading8,652,835 bytes. Its result SHA256 is `b70a8defdbbc46b09666fa1a588b072f8a16533971ee4ee4cce104430c35dbe7`. Neither audit reran model inference.
