## Conditional runtime boundary and acceptance

Only a synchronously qualified lookahead policy can justify a later runtime PR. Its private gate contract must bind source/exit depths, normalized input, direct-CDF versus hazard meaning, weights/config hashes, dtype and calibration. A pending result needs request ID, token position, completed/predicted depths and slot generation, plus device score storage, pinned host destination, completion event and owner. Start with one device and one recurrent traversal in flight; no general futures or serving framework is proposed.

The engine owns routing; the runner owns transfer completion. A decision applies once to its matching live token, coda waits for the selected loop, and last-exited propagation precedes later attention. Cancellation discards decisions without freeing outstanding readers/writers. A required wait is explicit when no independent work remains; do not add an extra loop to hide lateness. Same-gate synchronous/asynchronous history, RNG, KV and event/lifetime equivalence must precede a separately frozen end-to-end performance comparison including gates, copies, metadata, routing and drain.
